# Template: User's Art. 4(1) data access request

Produces a written user request to a data holder for IoT product and related service data under Article 4(1) of Regulation (EU) 2023/2854 (Data Act).

Form: short formal letter. Markdown by default. One page typical.

---

```
[User letterhead placeholder]

To: [Data holder, full legal entity name and registered address]
    [Optional: named recipient or department, e.g. "Data Act
    Contact Point" if published pursuant to Art. 3(2)]

Date: [Date of request]

Subject: Request for access to product data and related service
         data pursuant to Article 4(1) of Regulation (EU) 2023/2854
         (Data Act)

1. Identity of the requesting user

   The requesting party is [full legal entity name / natural person
   name], [registered office address / residential address where the
   user is a natural person]. [If the user is acting through a party
   on its behalf under Art. 4(1) second sentence: "[Acting party] is
   submitting this request on behalf of [user], pursuant to a
   mandate dated [date]. A copy of the mandate is enclosed."]

   The user is [the user of / the renter or lessee of / the owner
   of] [connected product identifier(s): model, serial number(s),
   VIN, asset ID, or other unique identifier] [where applicable: and
   the subscriber to the following related services: [service
   names]].

2. Data requested

   [Specific description of the data requested. Identify by
   category, by data field where known, and by time window. The
   request is for the data and the relevant metadata necessary to
   interpret and use the data.]

   The data requested falls within the scope of "product data" and
   "related service data" within the meaning of Art. 2(15) and
   2(16) of the Data Act. The user understands that the request
   covers readily available data, as defined in Art. 2(17), and
   does not extend to data that the data holder has obtained or
   would have to obtain through substantial investment beyond
   ordinary operation of the connected product or related service.

3. Legal basis

   This request is made under Art. 4(1) of the Data Act. Where
   data cannot be directly accessed by the user from the connected
   product or related service, the data holder is required to make
   readily available data, with the relevant metadata necessary to
   interpret and use the data, accessible to the user without
   undue delay, of the same quality as is available to the data
   holder, easily, securely, free of charge, in a comprehensive,
   structured, commonly used and machine-readable format and,
   where relevant and technically feasible, continuously and in
   real-time.

4. Format and delivery

   The user requests delivery [via secure file transfer to
   [endpoint] / via API access at [endpoint] / on physical media
   to the address above / via the data holder's published Data
   Act portal at [URL]]. [Where continuous or real-time delivery
   is technically feasible: "The user further requests that the
   data be made available continuously and in real-time from [date]
   onwards, in accordance with Art. 4(1)."]

   The user accepts machine-readable formats including [JSON / CSV
   / Parquet / Avro / specified industry standard]. Where the data
   holder proposes an alternative format, the user requests prior
   notice to confirm compatibility.

5. Purpose statement (optional, included only where useful)

   [Brief description of intended use, if the user chooses to
   disclose. Disclosure of purpose is not required to perfect the
   Art. 4(1) request. Where disclosed, the user notes that it is
   aware of the Art. 4(10) restriction against using the data to
   develop a connected product that competes with the connected
   product from which the data originate.]

6. Trade-secret pre-engagement

   The user acknowledges that some of the requested data may be
   identified by the data holder as trade-secret-protected. The
   user is prepared to engage in stage-1 negotiation under Art.
   4(6) regarding proportionate technical and organisational
   measures to preserve the confidentiality of any such data. The
   user requests that the data holder identify the specific
   categories of data it claims as trade-secret-protected and
   propose initial safeguards within [number] working days of
   receipt of this request.

7. Personal data

   [Option A, where the user is the data subject: "The user is the
   data subject for any personal data within the scope of this
   request. The user's data subject rights under Regulation (EU)
   2016/679 (GDPR), including under Art. 15, are reserved and are
   not affected by this Data Act request."]

   [Option B, where the user is not the data subject and is an
   enterprise: "The user is acting as a controller within the
   meaning of Regulation (EU) 2016/679 (GDPR) for the personal data
   within the scope of this request, in line with Recital 34 of the
   Data Act. The user's legal basis for processing under Art. 6(1)
   GDPR is [legal basis with brief substantiation]. The user has
   informed the affected data subject(s) of the processing in
   accordance with Arts. 13 and 14 GDPR."]

8. Timeline and response

   The user requests confirmation of receipt within [number]
   working days and substantive response without undue delay. Where
   the data holder anticipates a need to invoke Art. 4(6) (trade-
   secret safeguards), Art. 4(2) (security restriction), or any
   other limit on the request, the user requests notification
   within the same period so that any safeguards or limitations can
   be negotiated promptly.

9. Redress reservation

   This request is made without prejudice to the user's right to
   lodge a complaint with the competent authority designated
   pursuant to Art. 37 of the Data Act and the user's right to seek
   redress before a court or tribunal of a Member State.

[Signature block placeholder]

Enclosures (where applicable):
- Mandate from [user] to [acting party] dated [date]
- Proof of user status (purchase receipt, lease agreement,
  subscription confirmation) where the data holder may not have
  this on file
```
